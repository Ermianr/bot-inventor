# Single File Export is an esbuild ESM bundle emitted as `.mjs`

A spike (issue #2, verdict on #1) confirmed that discord.js bundles into one ~3MB file that runs on a bare Node.js installation with no `node_modules` present. We decided that **Single File Export is a single esbuild invocation producing ESM, written to `bot.mjs`**, rather than CommonJS or a `.js` file. This fixes ESM as the dialect the Compiler emits for **both** Export formats, so there is one generated-code style rather than two: CommonJS would force every generated bot to wrap its startup in an `async function main()`, because esbuild rejects top-level `await` in that format, and top-level `await` is how a generated bot logs in.

## Consequences

- **Three dependencies must be marked external, unconditionally**: `zlib-sync`, `bufferutil` and `utf-8-validate`. These are optional native addons that discord.js and `ws` probe for and fall back away from when absent. They cannot be bundled — they resolve to `.node` binaries, which esbuild has no loader for. The trap is that the build only fails when the addons happen to be installed on the machine doing the bundling, so a passing build proves nothing about another machine. The list is a constant of the Export step, never derived from the Project.
- **The ESM output needs a `createRequire` banner.** discord.js is CommonJS internally, and esbuild's interop emits a `__require` that throws `Dynamic require of "node:events" is not supported` on the first line of execution. The banner defines `require`, `__filename` and `__dirname` from `import.meta.url`. Without it the bundle is dead on arrival, so it is not optional decoration.
- **The extension is load-bearing.** An ESM bundle named `.js` runs only because Node 20.10+ detects module syntax. `.mjs` removes that dependency on the runtime's behaviour, which matters because we do not control the Node.js the user runs an Export on — only the sidecar used for Development Mode (see [ADR 0002](./0002-bundling-node-js-as-a-tauri-sidecar.md)).
- **Losing `zlib-sync` costs gateway payload compression, not functionality.** Exported bots trade some bandwidth for needing no install step.
- **The bot token is the only environment variable an Export requires.** The application id, which the Discord REST API needs to register slash commands, is available as `client.application.id` once the gateway handshake completes. Registering commands after `ready` rather than through an up-front REST call means we never ask the user for it, which keeps the Secret surface at exactly one value.
